# Аудит рекламы кабинета маркетплейса

Реализация на этом сервере: `/root/ozon-agent/ads_audit.py`
(`python3 ads_audit.py <кабинеты> --brand X --phrases --alias x --alias х`),
первый прогон — `docs/analysis/2026-09-24-inki-ads.md`. Ниже — метод, он
переносится на любой кабинет и маркетплейс.

## Метод

1. **Товары бренда — по полю «Бренд» карточки**, не по названию
   (Ozon атрибут 85, WB `brand`). В названиях бренд почти не пишут: по имени
   нашлось 0,4 млн из реальных 12,9 млн. Карточки с пустым брендом —
   отдельный список «заполнить», они выпадают из разреза.
2. **Порог — безубыточный ДРР по SKU, а не общая цель.**
   ДРР_бе = маржа до рекламы / цена. Маржу брать из фактического отчёта
   (у нас портал 66 Ozon / 2 WB: всё кроме ФОТ и налога), поправить на
   текущую цену и комиссию. Цель = ДРР_бе минус ФОТ (~7,5 %).
   Классы: убыточно (ДРР > ДРР_бе), ниже цели, окупается, недоинвестировано
   (ДРР << цели и бюджет не выбирается).
3. **Сначала остатки, потом ставки.** Поднимать ставку на SKU с остатком
   < 14 дней бессмысленно; главный тормоз часто склад, а не реклама.
   Убирать SKU из РК из-за 2–4 дней остатка — копейки выгоды и ручной
   возврат после поставки; сначала спросить, едет ли поставка.
4. **Бюджет vs ставка.** Если РК с лучшим ДРР не выбирает бюджет — растить
   ставку шагом 10 %, а не бюджет.
5. **Фразы.** Считать долю расхода на СВОЙ бренд (у нас 30–41 %) и фразы
   с кликами без заказов. Свои кабинеты на одном товаре конкурируют между
   собой за брендовый запрос. Прирост от брендовой рекламы vs перехват
   органики — только тестом 14 дней по ВСЕМ заказам SKU, не рекламным.
6. **Динамика по неделям** по каждому кабинету: резкое падение расхода
   при падении заказов — проверить бюджеты/баланс РК в ЛК.

## Ловушки данных

- Ozon «рекламные заказы» — атрибуция Ozon, включает органику; доля
  рекламных заказов ≠ прирост.
- WB: расход по РК — из списаний (реальные деньги); расход по товарам из
  fullstats включает кэшбэк (+1–6 %). Выручка WB по заказам — с отменами (~8 %).
- Прибыль-оценка по заказанным штукам оптимистична (без возвратов).
- Кеши экономики могут быть посчитаны до дозагрузки дней — брать из базы.
- WB статистика рекламы: 1 запрос/час/кабинет, normquery блокирует на
  5–12 мин после 1–2 запросов — не гонять аудит чаще раза в час.

## Что умеет API в чистке ключей

- **WB:** читать статистику фраз (`/adv/v0/normquery/stats`) и минус-фразы
  (`get-minus`), писать — `set-minus`. Автоматизировать можно (с гейтом).
- **Ozon:** минус-фраз в API нет; отчёт по фразам только для РК «Поиск»
  и без расхода/заказов. Чистку делает человек в ЛК; автоматизация ЛК
  браузером запрещена офертой (Оговорка об ИБ п. 2.2–2.4).

## Выход

5 главных выводов → таблица по кабинетам (расход, рекл. выручка, ДРР,
TACoS, доля рекл. заказов, ДРР_бе, прибыль-оценка) → предложения с
эффектом в ₽. Живые изменения — только через очередь с подтверждением
человека (реклама = деньги, см. [[confirm-gated-integration]]).
