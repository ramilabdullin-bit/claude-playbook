# Молчаливый ретрай = потерянный заказ

Фоновый обработчик (cron каждые N минут) берёт заказ, упирается в
недостающие данные, пишет строчку в лог и `continue` — «попробуем в
следующий проход». Следующий проход упирается в то же самое. И так сутки.

Человек в панели видит «заказ принят, фабрика делает» и ждёт. Владелец
приходит с «почему заказ не дошёл?» — и причина всё это время лежала в
логе, дословно, 48 раз подряд.

**Реальный случай (content-factory, 07-08.09.2026):** два заказа видео
висели сутки, каждые полчаса в логе
`нет исходных фото карточки для вырезки — забирать нечего`.
Никто не читает логи фабрики.

## Правило

Если обработчик умеет сказать «не могу, жду», он обязан уметь сказать это
**тому, кто заказал**, а не только в лог.

```python
STUCK_AFTER = 3          # холостых проходов терпим молча

def _report_stuck(brief, why, log):
    sig = f"{brief['task']}|{brief['sku']}|{brief['marketplace']}"
    state = json.loads(STUCK_STATE.read_text()) if STUCK_STATE.exists() else {}
    rec = state.get(sig) or {"passes": 0, "reported": False}
    rec["passes"] += 1
    if rec["passes"] >= STUCK_AFTER and not rec["reported"]:
        proposals.add_task(brief["cabinet"], f"… {why[:180]} …", by="фабрика")
        rec["reported"] = True
    state[sig] = rec
    STUCK_STATE.write_text(json.dumps(state, ensure_ascii=False))
```

Три обязательных свойства:

1. **Порог, а не первый же промах** — временная блокировка (лимит API,
   недогруженный файл) рассасывается сама, дёргать человека рано.
2. **Флаг `reported`, отдельно от `passes`** — сообщение ровно одно на
   заказ, иначе получится спам каждые полчаса, что не лучше тишины.
3. **Причина дословно из исключения** (`str(e)[:180]`), а не «ошибка
   обработки» — человек должен понять, что сделать: доснять фото,
   починить доступ, отменить заказ.

Состояние — отдельный маленький JSON рядом с очередью; в саму очередь
блокировку не пишем, иначе заказ считается обработанным и не поедет,
когда причина уйдёт.

## Сопутствующая грабля: авто-подтягивание сделали для одного канала

Та же поломка началась с того, что автозагрузка исходников была написана
под один маркетплейс (Ozon), а фетчеры второго (WB) складывали файлы в
другие папки — и ветка «а если пусто, сходи забери» для него просто не
существовала. Симптом выглядел как «нет данных», причина была «не сходил».

Проверяя «почему пусто», сначала посмотри, **вызывается ли вообще**
загрузчик на этом пути, и **в ту ли папку** он пишет по сравнению с тем,
где ищет потребитель. См. [[marketplace-agent-parity]] — расхождение
возможностей между каналами тут же превращается в такой инцидент.
