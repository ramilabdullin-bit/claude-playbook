# Временный хостинг по имени файла отдаёт чужой файл

## Инцидент (2026-09-24, ozon-agent + content-factory)

Видео для Ozon выкладывалось в kie.ai (`file-base64-upload`) с `uploadPath="mp/inki"`,
`fileName="director.mp4"` — у ВСЕХ роликов фабрики одно имя. kie.ai на одно имя
отдаёт один URL и молча перезаписывает содержимое. Ozon по уже знакомому URL
не перекачивает и ставит ролик, забранный раньше: на карточку АКВАРОСЫ встал
ролик крема INKI. Ответ импорта — `imported`, ошибок ноль. Заметил владелец на витрине.

Та же схема была у фабрики для входных кадров генерации (`packshot.jpg` у 12 SKU —
одна ссылка): подмены не случилось только потому, что прогоны шли строго по очереди.

## Правило

1. **Имя файла = хэш содержимого** (`sha256(bytes)[:16] + ext`). Разный файл —
   разный URL, тот же файл — тот же URL (это ок).
2. **После загрузки скачать URL и сверить sha256 с локальным.** Не совпало —
   падать ДО платной генерации / до передачи потребителю.
3. **Потребитель, который дедуплицирует по URL или содержимому (Ozon),
   проверяется отложенным чтением результата**: скачать итоговый медиа-файл с его
   CDN и сравнить с нашим (SSIM кадров ≥0.9), а не верить `imported`.
4. Старые записи вида «общее имя» (кэш URL в json) — считать недействительными и
   перевыкладывать.

## Как снять неправильное видео с карточки Ozon

`/v3/product/import` со снимком без группы 100001 (или `/v1/product/attributes/update`
с пустыми `values` для 21841/21837) — API сразу показывает пусто, витрина
отстаёт ~30–60 мин. Проверять глазами на ozon.ru (с сервера витрина за анти-ботом).
