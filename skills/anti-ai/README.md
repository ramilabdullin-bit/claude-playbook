# anti-ai

Скилл для Claude Code. Берёт русский текст и убирает из него следы машинной
генерации: типографику, симметрии, канцелярит, шаблонные крючки, ровный ритм,
неидиоматичные обороты, и при этом смысл, факты, структура и авторская лексика
остаются на месте.

Работает с тремя видами текста: письменным, речью под суфлёр и расшифровкой
живой речи, и у каждого свой профиль порогов.

## Установка

```bash
git clone https://github.com/artemiimillier/anti-ai-skill.git ~/.claude/skills/anti-ai
```

Только для одного проекта - в `.claude/skills/anti-ai` внутри репозитория.

Проверка: в Claude Code скилл появляется в списке доступных под именем `anti-ai`.

## Как позвать

Словами в обычном сообщении:

- «убери ИИ из этого текста»
- «почисти текст от ИИ»
- «текст звучит как нейросеть, перепиши»
- «сделай текст человечным»
- «почисти расшифровку эфира»
- «прогони через anti-ai»

Либо явно: `/anti-ai` и следом текст или путь к файлу.

## Что происходит

Сначала три вопроса: канал (эфир или расшифровка, мессенджер, письмо, страница
продукта, договор), профиль запуска и путь к папке с текстами автора. Канал
включает обязательные словари, профиль задаёт пороги, папка с текстами даёт
проверку «автор это слово говорил» и перезамер порогов под него. Папки нет -
скилл говорит об этом сразу: часть находок дальше держится на вкусе, и они
помечаются в отчёте.

Дальше пять этапов, каждый со своим условием выхода:

1. **Диагностика** - считает и цитирует, ничего не правит.
2. **Механическая чистка** - типографика, канцелярит, штампы, кальки и семь
   словарей, первым юридический.
3. **Семантический проход** - антитезы, крючки, анонсы, повторы, каркасы,
   обвинение читателя.
4. **Ритм** - отдельным проходом, потому что правки этапов 2 и 3 портят ритм.
   На расшифровке пропускается: пунктуацию в ней ставила распознавалка.
5. **Чтение вслух и приёмка** - неидиоматичность, проверка замен на затёртость
   и приёмка по шести вопросам.

Приёмка меряет две стороны сразу: маркеров нет и сильные места исходника
остались сильными. Текст с нулём маркеров, из которого ушёл голос автора,
приёмку не проходит, а предел работы - три полных прохода, дальше стоп
с отчётом об остатке.

## Надиктовка и расшифровка

Черновик автора идёт в работу сырьём. Машинный такт чистится одинаково
в сгенерированном тексте и в собственной надиктовке. Заморожено ровно то, что
автор пометил похвалой: такой кусок переносится дословно.

Живая речь считается по своему профилю. Слова-паразиты, самоперебивы и повторы
идут в нём справкой и вердикт не валят. Порог по филлеру задаётся сравнением
автора с самим собой по его же корпусу.

## Инструменты

Чистый Python 3 без внешних зависимостей, и эти два скрипта запускаются
отдельно от скилла тоже.

```bash
python3 tools/diagnose.py текст.md                      # полный отчёт
python3 tools/diagnose.py текст.md --profile speech     # речь под суфлёр
python3 tools/diagnose.py текст.md --profile transcript # расшифровка живой речи
python3 tools/diagnose.py текст.md --only rhythm        # только ритм
python3 tools/diagnose.py текст.md --json               # машинный вывод
cat текст.txt | python3 tools/diagnose.py -

python3 tools/diagnose.py --calibrate corpus/ --name imya  # пороги под автора
python3 tools/diagnose.py --selftest                       # порядок профилей

python3 tools/fix-typography.py текст.md --report   # что будет заменено
python3 tools/fix-typography.py текст.md --in-place # заменить
```

`diagnose.py` считает 26 осей находок, плотность на 1000 слов, разброс длин
предложений и долю абзацев с коротким финалом. Коды выхода: 0 - в пределах
порогов, 1 - есть провалы, 3 - ошибка ввода.

`--calibrate` берёт папку с готовыми текстами автора, печатает сырые плотности
по файлам и осям и выдаёт готовый блок порогов по p90. Он нужен там, где текст,
который автор считает своим и хорошим, валится по одной и той же оси два раза
подряд.

`fix-typography.py` меняет только однозначное: длинное и короткое тире, многоточие
одним символом, типографские кавычки и апострофы, неразрывный пробел, символы
нулевой ширины, лишнее экранирование. Блоки кода и строчный код не трогает.

## Чего скилл не делает

Факты, цифры, имена и термины автора остаются как есть. Объём не сокращается
больше чем на 12%, смысловые блоки остаются на месте, живые авторские обороты
не «улучшаются» до более грамотных. Слабую авторскую фразу скилл не заменяет
гладкой пустотой: замена слабее оригинала в текст не идёт, альтернатива уходит
в отчёт. Ничего не выдумывается, включая объяснение нераскрытого термина:
вместо него в отчёт идёт вопрос человеку.

## Оговорка про самопроверку

`tools/diagnose.py` написан под связный текст, который читает человек: пост,
письмо, статья, сценарий. Справочные файлы самого скилла он проверку не
проходит, и это ожидаемо. В них лежат таблицы с примерами того, что запрещено,
а инструмент видит эти примеры как употребление. Плюс документация написана
безлично, а у прозы он требует живого «я».

Перед тем как править находку, посмотри на цитату. Совпадение внутри примера
или внутри блока кода это шум.
