# Набор команд для проверки

Команда копируется дословно. Самодельное «более точное» выражение систематически
даёт заниженный результат и зелёный отчёт на грязном тексте. Замеренный случай:
самодельное выражение нашло 1 нарушение при лимите 1, канонический вариант на том
же файле нашёл 8. Самодельный требовал отрицания в начале клаузы, живые нарушения
стояли в середине предложения.

Дословность действует для команды, которая отработала. Порядок такой:

1. Команда упала, либо её находки очевидно мусорные, либо она молчит на заведомо
   грязной строке. Тогда правится сам шаблон: здесь, в этом файле, и синхронно
   в `tools/diagnose.py`.
2. Исправленный вариант снова копируется дословно.

Подгонять выражение под конкретный текст, чтобы отчёт позеленел, запрещено.
Разница между правкой и подгонкой: правка остаётся в файле для всех будущих
прогонов и меняет число находок на всём корпусе, подгонка живёт один раз.

Где вариантов несколько - прогонять **все** и объединять по позиции совпадения,
чтобы не считать одно нарушение дважды.

## Что считается проверкой

Коды выхода `rg` и `grep`: `0` - находки есть, `1` - находок нет, `2` и выше -
ошибка. Чистым текст объявляется только по коду `1`. Код `2` (сломанный шаблон,
нет такого файла) и код `127` (в оболочке нет самой программы) значат, что текст
не проверен, и в отчёт идёт строка «проверка не отработала» с именем команды.

Команды запускаются прямо в оболочке. `rg` иногда живёт функцией или алиасом
(покажет `type rg`), и тогда из отдельного скрипта-файла она не видна: код `127`
на всех проверках подряд.

Перед первым прогоном на новой машине - канарейка. Она подаёт заведомо грязную
строку и требует находку:

```bash
printf 'канарейка \xe2\x80\x94 является\n' | rg -q '[\x{2014}]' \
  && echo "движок понимает набор" \
  || echo "движок не понимает \x{...}: команды типографики недействительны"
```

Вторая ветка канарейки значит, что все команды с `\x{...}` вернут «чисто» на
любом тексте, включая заведомо грязный.

## macOS: системный grep

`/usr/bin/grep` в macOS - BSD grep. Он ломает набор двумя способами: громким
падением и тихим нулём находок. Тихий опаснее.

| Что | Поведение BSD grep | Чем опасно |
|---|---|---|
| `grep -P` | падает, `invalid option -- P`, код `2` | видно сразу |
| `\x{2014}` и другие кодовые точки | находок нет, код `1` | грязный текст объявлен чистым |
| `\d`, `\S` внутри `-E` | находок нет, код `1` | то же |

Замеренный прогон: строка с длинным тире и типографскими кавычками дала у BSD
grep пустой вывод и код `1`, у `rg` на том же файле - находку.

Чем считать:

```bash
command -v rg || command -v ggrep || echo "нужен ripgrep либо GNU grep"
```

- `rg` (ripgrep) - все команды набора работают как записаны;
- `ggrep -nP 'ШАБЛОН' FILE` - GNU grep из пакетного менеджера, синтаксис PCRE
  понимает `\x{...}`;
- `python3 tools/diagnose.py FILE` - считает те же оси без внешних команд,
  только стандартная библиотека.

Если под рукой один системный grep, типографика проверяется классом из самих
символов, собранным через `printf`:

```bash
/usr/bin/grep -n "$(printf '[\xe2\x80\x94\xe2\x80\x93\xe2\x80\xa6\xe2\x80\x9c\xe2\x80\x9d\xe2\x80\x98\xe2\x80\x99\xc2\xa0]')" FILE
```

Упавшая или промолчавшая на канарейке команда - это непроверенный текст.
Записывать по ней «чисто» нельзя.

## Ложные срабатывания по корню слова

Поиск по куску слова ловит соседние слова с тем же куском внутри:

| Ищем | Ловит заодно |
|---|---|
| `лекци` | коллекции, коллекционер |
| `конте` | контекст и контент сразу, слова из разных словарей |
| `курс` | курсор, курсив, экскурс, курса валют |
| `явля` | появляется, объявляется, проявляется, заявляется |

Порядок работы с этим:

1. Ставить границу слова `\b`, когда ищется целое слово. `\b` работает и в `rg`,
   и в BSD `grep -E`.
2. Отсеивать известных соседей вторым проходом. Просмотра назад в `rg` нет
   (появляется только с `rg -P`), поэтому фильтр идёт трубой:

```bash
rg -ni '\b(лекци|курс|контент)\w*' FILE | rg -vi '(коллекци|курсор|курсив|экскурс|курса валют|контекст)'
```

   У трубы код выхода берётся от последнего звена, поэтому здесь «чисто»
   определяется по пустому выводу, а исправность движка - канарейкой выше.

3. Ложное срабатывание закрывается пометкой в отчёте: файл, строка, слово,
   причина. Строка остаётся в отчёте с пометкой «ложное». Удалять её нельзя:
   следующий прогон найдёт то же место заново и разбор пойдёт по второму кругу.

Массовая автозамена по отчёту запрещена: ни `sed -i` по списку находок, ни
«заменить все» в редакторе. В отчёте лежат вперемешку нарушения и ложные
срабатывания, автозамена правит их одинаково. Каждое место правится отдельно,
с чтением строки целиком.

## Типографика (лимит 0)

```bash
rg -n '[\x{2014}\x{2013}\x{2026}\x{201C}\x{201D}\x{2018}\x{2019}]' FILE
rg -n '[\x{200B}\x{200C}\x{200D}\x{FEFF}\x{00A0}\x{2028}\x{2029}]' FILE
rg -n '\\[.!\-*]' FILE
```

## Симметрии (суммарно не больше 1 на текст)

```bash
# прямой порядок
rg -n ' не [^.,;:!?]{1,40}, а [^.,;:!?]{1,40}' FILE
# тот же оборот с заглавной, в начале клаузы или после жирного маркера
rg -n '(^|[.!?»)]\s+|\*\*\s?)[Нн]е [^.,;:!?]{1,45}, а [^.,;:!?]{1,45}' FILE
# инверсия
rg -n ', а не ' FILE
# разрыв через точку, подлежащее любое
rg -ni '(это|дело|она|он|оно|модель|память|файл)\s+не\s+[^.,;:!?]{1,45}[.,-]\s*(это|дело)\s' FILE
# зеркало через «ты», регистр любой: в начале предложения стоит «Ты не ...»
rg -ni '\bты не [^.,]{1,40}, ты ' FILE
# то же зеркало на «вы»
rg -ni '\bвы не [^.,]{1,40}, вы ' FILE
```

Замеренный прогон без `-i`: строка «Ты не докручиваешь промпт, ты меняешь
правила» не нашлась, а та же фигура строкой ниже, в середине предложения,
нашлась. Отчёт скрипта её при этом показывал, и расхождение двух слоёв
закрывается правкой шаблона; выбирать из двух чисел удобное запрещено.

## Стаккато: три коротких предложения подряд (в теле текста лимит 0)

Якоря на строку целиком тут нет. В размеченном тексте цепочка стоит внутри
абзаца и таскает на себе звёздочки жирного и курсива.

```bash
rg -n '\**[А-ЯЁA-Z][а-яёa-z]{1,15}\**[.!]\**\s+\**[А-ЯЁA-Z][а-яёa-z]{1,15}\**[.!]\**\s+\**[А-ЯЁA-Z][а-яёa-z]{1,15}\**[.!]' FILE
```

Замеренный прогон с якорями `^...$`: код `1` на трёх строках подряд, где
цепочки стояли в середине абзаца, в жирном и в курсиве.

Ложные срабатывания: три коротких пункта списка в одну строку, подпись внутри
цитаты. Инициалы вида «А. С. Иванов» не ловятся, после заглавной требуется
минимум одна строчная буква.

## Связка «является» (служебная позиция)

Голый поиск `является` внутри общего списка ловил «появляется», «объявляется»,
«проявляется», «заявляется». Нарушением эти слова не бывают, поэтому слово
вынесено отдельной командой с границей:

```bash
rg -n '\bявля(ет|ют)ся\b' FILE
```

Ловится позиция связки между подлежащим и именной частью: «X является Y».
Редкое «является в кадре» закрывается пометкой ложного срабатывания.

Тот же случай закрыт в `tools/diagnose.py`, список `CLERICAL`: шаблон там стоит
с ограничением справа и на приставочные формы тоже не срабатывает. Оба слоя
обязаны молчать на приставочных формах. Расхождение чисел между отчётом скрипта
и этой командой значит, что словари разошлись. Тогда шаблон приводится к одному
виду в обоих файлах. Выбирать из двух чисел удобное запрещено.

## Безличное и крючки внутри абзаца

```bash
rg -ni '(тебе расскажут|ты узнаешь|вам расскажут|вы узнаете|здесь объяснят|здесь покажут|давайте разберём|давайте рассмотрим|важно понимать что|обрати(те)? внимание|следует помнить|и самое (мощное|интересное|важное)|вот в чём суть|а теперь представь|и тут начинается интересное|самое интересное|самое важное|главное запомнить)' FILE
```

Формула, записанная на «вы», по тексту на «ты» не срабатывает никогда.
Проверять оба обращения.

## Шаблонные старты и финалы

Старт ищется в начале предложения. Якорь на начало строки пропускает «Сегодня
поговорим» третьим предложением абзаца, а ещё любой старт под решёткой
заголовка, под знаком цитаты и в пункте списка.

```bash
rg -ni '(^[#>*\s-]{0,6}|[.!?»)"]\s+)(привет,? друзья|здравствуйте,? дорогие|сегодня поговорим|сегодня я хочу поделиться|в этой (статье|заметке) (вы|ты) узнае)' FILE
rg -ni '(спасибо за внимание|подписывайтесь на канал|жду вас в комментариях|до новых встреч|и теперь ты понимаешь|именно поэтому|будущее за теми|это и есть)' FILE
```

Замеренный случай: вариант с `^(...)` вернул код `1` на трёх строках подряд, где
шаблонный старт стоял третьим предложением, под заголовком и в цитате.

## Словарные проверки: ловят слово

Пять словарей Этапа 2 не ловятся ни одной проверкой на машинность. Замеренный
случай: 281 слово с «школой», «учениками», «домашкой», «оффером», «лендингом»,
«кейсом», «MVP», «синергией» и «голубым океаном» прошло все оси машинности
чисто и свалилось только по ритму, случайно. Поэтому словари проверяются
отдельными командами, и в `tools/diagnose.py` им отвечают пять осей:
`legal`, `anglicism`, `corporate`, `pseudoproof`, `metaphor`. Лимит у каждой
ноль. Расхождение чисел между отчётом скрипта и этими командами значит,
что словари разошлись: шаблон приводится к одному виду в обоих файлах.

Сверять числа только по совпадениям, не по строкам. В размеченном тексте абзац
лежит одной строкой, и три нарушения в нём `rg -n` покажет как одну находку.
Для сверки со скриптом команда запускается с `-o`, счёт берётся по строкам
вывода:

```bash
rg -nio 'ШАБЛОН' FILE | grep -c .
```

Замеренный прогон на грязном файле: по строкам псевдопруфы дали 2, по
совпадениям 5, отчёт скрипта - 5. Числа сошлись только во втором счёте.

### Юридический словарь (лимит 0, прогоняется первым)

Поиск по корням, не по целым словам. Вторая команда ловит «ДЗ» - там важен
регистр, поэтому `-i` в ней нет.

```bash
rg -ni '(онлайн-школ|школ|\bкурс([аыоуеим]|ов|ах|ами|ом)?\b|обуч|урок|образовани|образовательн|ученик|ученич|студент|преподава|учител|домашн|домашк)' FILE | rg -vi '(курсор|курсив|курсант|экскурс|курса валют|курс валют)'
rg -n '\bДЗ\b' FILE
```

`\bкурс` без хвоста слова ловит «курсор», «курсив», «экскурс» и «курс валют»,
поэтому хвост перечислен целиком, а известные соседи отсеиваются трубой.
У трубы код выхода берётся от последнего звена: «чисто» тут определяется
по пустому выводу, исправность движка - канарейкой из начала файла.

Слово остаётся на месте в трёх случаях канона (цитата чужой речи, имя
стороннего продукта, сознательная юридическая формулировка). Каждый такой
случай остаётся в отчёте строкой с пометкой «ложное» и причиной.

### Англицизмы при живом русском слове (лимит 0 в письменном тексте)

```bash
rg -ni '(\bоффер|\bлендинг|\bл[эе]ндос|\bкейс|\bконтент|\bдеплой|\bдеплоит|\bзадеплои|\bmvp\b|\bфидб[эе]к)' FILE
```

«Оффер» пишется с двойным «ф»: `оферта` - юридический термин и под команду
не попадает. В устном и разговорном тексте действует обратная оговорка канона:
находка закрывается пометкой в отчёте, слово остаётся английским.

## Фальшивый диалог

```bash
rg -n '\?' FILE
```

Каждый вопросительный знак оправдывается вручную. По умолчанию их близко к нулю:
настоящий вопрос к читателю остаётся, вопрос-затычка с ответом следом убирается.
