# 529 Overloaded в headless `claude -p` притворяется поломкой кода

Перегрузка API выглядит так:

```
rc=1
stop_reason: "stop_sequence"
usage.input_tokens: 0
total_cost_usd: 0.0009
stderr: (пусто или безобидное предупреждение про stdin)
```

Ни слова про перегрузку. Причина лежит в JSON:

```json
{"is_error": true,
 "result": "API Error: 529 Overloaded. This is a server-side issue, usually temporary…"}
```

## Почему это дорого стоит

03.09.2026 в `lawyer-agent`: вызов упал через минуту после того, как я поменял
системный промпт. Журнал службы обрезал строку ошибки на 500 символах, поле
`result` в неё не попало. Вывод «я сломал» выглядел неопровержимым: до правки
десятки удачных вызовов, после — отказ. Откатил рабочую версию, выстроил
гипотезу про «сессию нельзя возобновить с изменённым промптом», начал
переделывать архитектуру — и только бисекция флагов показала, что **со старым
промптом падает точно так же**.

Мораль: прежде чем верить в собственную вину по времени события, прогони
контрольный опыт БЕЗ своей правки. Совпадение по времени — не доказательство.

## Как проверять

```python
d = json.loads(r.stdout)
print(d.get("is_error"), str(d.get("result"))[:200])
```

Голый вызов как контроль (без своих флагов):

```bash
claude -p "скажи ок" --output-format json < /dev/null | head -c 400
```

Он может пройти, пока ваш падает: перегрузка приходит волнами. Один удачный
контрольный вызов НЕ снимает подозрение с перегрузки — нужны повторы.

Логируя ошибку, не режь `result`: `logger.error("%.500s", details)` съедает
именно то место, где написана причина.

## Как лечить

Повтор с паузой, и только для перегрузки — истёкшую авторизацию или таймаут
повторять бессмысленно:

```python
def _is_overload(details: str) -> bool:
    low = details.lower()
    return "529" in low or "overloaded" in low
```

Пауза берётся ВНЕ блокировок. Спать, держа `flock`, значит запереть и
остальные запросы: у одного пользователя незаметно, у бота с несколькими
собеседниками — нет.

Перегрузка приходит двумя путями, проверять надо оба: код возврата 1 с текстом
в stdout/stderr И код возврата 0 с `is_error: true` в теле JSON.

Пользователю отвечать по-человечески («сервис перегружен, попробуйте через
минуту»), а не «Ошибка при обращении к CLI»: иначе он не знает, что достаточно
повторить.

лежит в stdout, а не в stderr.
