# Общий компонент проверяй везде, где он живёт

Форма Contact Form 7, шапка, виджет, шорткод, общий partial — одна разметка,
но рендерится она внутри разных страниц: тёмная тема и светлая, узкая
колонка и широкая, страница с чужим CSS-предком. Правка, выверенная на
одной странице, на другой ломается **без ошибки**: ничего не падает, просто
текст белый по белому или блок вылез из сетки.

Случай (e-comportal, 2026-09-21): в общую форму добавили `<select>` города.
Тема красит `input` белым только под `.theme-dark`, а про `select` не знает —
на тёмной странице он был тёмным по тёмному. Поставил `color:#fff!important`,
проверил на той же тёмной странице — «ок». На /kontakty/ и в постах (светлые)
выбранный город стал белым по белому. Поймано случайно, на превью другой
страницы, уже после «проверил, работает».

## Что делать

1. **До правки — список контекстов.** Где компонент встречается? Для WP:
   `grep`/поиск шорткода по шаблонам, либо обойти 4–6 типовых URL и
   проверить наличие селектора. Минимум: по одной странице на каждую
   тему/шаблон (тёмная, светлая, пост, главная).
2. **Найди переключатель контекста, а не лепи `!important`.** Посмотри, каким
   правилом тема красит соседние поля (`.theme-dark .form-control input{…}`)
   и повтори ту же пару: значение по умолчанию + оверрайд под тем же
   предком. Свой элемент должен наследовать поведение соседей.
3. **Проверка — сравнением с соседом, на каждом контексте.** Не «выглядит
   нормально», а машинно: computed `color`/`height` нового элемента ==
   computed у соседнего штатного поля, в цикле по всем URL из п.1:

   ```python
   for url in CONTEXT_URLS:
       page.goto(url + f"?v={time.time()}")          # мимо кэша
       print(url, page.evaluate("""() => {
         const a = getComputedStyle(document.querySelector('select[name=city]'));
         const b = getComputedStyle(document.querySelector('input[name=email1]'));
         return {same_color: a.color === b.color, a: a.color, b: b.color}}"""))
   ```
4. Скриншот хотя бы по одному контексту каждого типа — глазами.

URL), [[verification-before-completion]].
