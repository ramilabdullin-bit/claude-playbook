# Отдать сотруднику настройку, а не держать её в коде

Каждая мелочь по виду инструмента («окно маленькое», «шрифт мелкий»,
«убери этот раздел») приходит разработчику, ждёт очереди и возвращается
через день. Сотрудник перестаёт просить и перестаёт пользоваться.

**Формулировка владельца (08.09.2026):** «настройку окна общения передаю
сотрудникам, полный карт-бланш, иначе они не будут агентами
пользоваться».

## Правило

1. **Настройки ЛИЧНЫЕ, ключ — сотрудник.** Не на кабинет и не глобально:
   двое работают по-разному, подгонка одного не должна ломать вид другого.
2. **Схема с проверкой и человеческим объяснением в одном месте:**
   `{ключ: (умолчание, правило, «что это значит словами»)}`. Из неё
   генерируются и форма, и справка для агента, и валидация. Негодное
   значение возвращает понятную строку, а не трассировку, и НЕ затирает
   годное.
3. **Два входа, одна логика.** Кнопка в интерфейсе — и та же команда у
   агента (`settings.py set <кто> <ключ> <значение>`). Просить человека
   лезть в настройки, когда рядом есть агент, которому можно сказать
   «сделай окно выше», — лишний шаг.
4. **Правило в промпте агента:** такие просьбы выполняй САМ. Иначе агент
   добросовестно отправит их разработчику (см.
   [[agent-cannot-fix-itself]]) — и карт-бланш не заработает.
5. **Граница явная.** Настройкой меняется вид; всё, чего настройкой не
   сделать (новая колонка, другая формула, новый источник данных), —
   по-прежнему заявка разработчику. Границу пишем прямо в промпт, иначе
   агент будет либо всё слать наверх, либо обещать невозможное.

## Реализация без переписывания разметки

Порядок блоков переключается **CSS-свойством `order`** на flex-контейнере,
а размеры — инлайновым `<style>` из настроек. Тогда «подними очередь
наверх» и «сделай окно выше» — это две строки CSS, а не перестановка
шаблона, которую страшно трогать.

Фоновые уборщики (ночные кроны) обязаны слушать те же настройки: если
сотрудник просил «не сбрасывай переписку по утрам», крон не имеет права
её сбросить. Иначе настройка выглядит сломанной.
