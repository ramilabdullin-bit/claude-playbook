# Проверка после «готово»: 5 пунктов по кругу

**Когда применять:** после того как оркестратор или агент сказал «готово». Крутить по кругу: пункт 5 возвращает на доработку, потом заново пункты 1-5, пока всё не сойдётся с тем, что просил.
**Источник:** практикум СмыслоКод, август 2026, День 1, шаг 8.1 (`training/source/prompts/aug-day1-karkas-instruction.md`); финальные проверки дня оттуда же и из `aug-day2-skill-instruction.md`; `training/dashboard-review.md` §3.2.

## Промпт

```prompt
Проверь свою работу по пунктам, отвечай по каждому отдельно:
1. Убедись, что это лучшее решение задачи. Какие варианты ты рассмотрел и почему выбрал этот?
2. Убедись, что подумал на несколько шагов вперёд: что сломается, когда данных станет больше и когда придёт следующая задача поверх этой.
3. Убедись, что в коде нет ошибок и он безопасный. Отдельно проверь ключи, доступы и данные людей - ничего из этого не должно попасть в видимую часть.
4. Запусти это и покажи, что работает.
5. Если что-то не сходится с тем, что я просил, - чини сам и показывай заново.
Всегда отвечай на русском.
```

## Финальная проверка дня: «да / нет» по списку

Формат из практикума - агент показывает дерево проекта и по каждому пункту отвечает «да» или «нет» с пояснением, что не выполнено - чинит сам и показывает заново. Список подставляется свой (у Дня 1: idea.md заполнен, CLAUDE.md короче 200 строк и 5 разделов, `.business/` с INDEX, `rules/`, хуки срабатывают, план в фазах, запрет публикации без разрешения).

```prompt
Покажи дерево моего проекта и проверь по пунктам, отвечая да или нет с пояснением:
1. [пункт]
2. [пункт]
...
Что не выполнено - почини сам и покажи заново.
Всегда отвечай на русском.
```

## Адаптация под Контент-завод

- Пункт 4 «запусти и покажи» для завода = прогон узла на тестовом сырье с выводом поста целиком и JSON ответа площадки (в тестовом канале), не «код компилируется».
- Пункт 3 расширить: токены площадок только из окружения, в диффе нет ключей, в постах нет ПДн клиентов складов.
- Список для финальной проверки фазы - DoD из `plans/`: исполняемая команда с негативным случаем.
- Это самопроверка исполнителя; независимая приёмка - `acceptance.md` и `.claude/agents/qa-acceptor.md`.
