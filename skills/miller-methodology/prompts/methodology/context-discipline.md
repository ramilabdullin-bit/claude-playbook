# Дисциплина контекста: правило сорока процентов

**Когда применять:** в начале большой задачи, чтобы задать контекст-дисциплину на всю сессию. Когда чувствуешь, что качество ответов агента деградировало - это симптом переполненного контекста.
**Источник:** Артемий Миллер, промпт №9 «Progressive Disclosure + 40% Rule» (`training/source/promty/disciplina-konteksta-pravilo-soroka-procentov.md`). Краткая версия правила - в `CLAUDE.md`, «Ключевые принципы».

## Промпт

```prompt
Правила управления контекстом на эту сессию:

1. ПРАВИЛО 40%
   Держи контекст в диапазоне 40-60% окна.
   В районе 50% делай ручной /compact - не жди автокомпакта.
   Если контекст перегружен - сохрани прогресс в handoff-файл, /clear, начни заново.

2. PROGRESSIVE DISCLOSURE
   Не вываливай в контекст всю кодбазу.
   - Research: подключай sub-агентов, бери от них компактные саммари.
   - Planning: только саммари + ключевые интерфейсы, не полные файлы.
   - Implementation: только файлы текущей фазы.
   - В CLAUDE.md ссылайся на пути к докам, а не @-импортируй файлы.

3. FRESH CONTEXT МЕЖДУ СТАДИЯМИ
   Каждая большая стадия = чистое окно.
   Перед /clear создай handoff-файл с прогрессом и контекстом для следующей стадии.

Эти правила важнее скорости. Лучше /clear лишний раз, чем работать в Dumb Zone.
```

## Почему работает

Качество кода LLM падает после 40-50% заполнения окна контекста («Dumb Zone»). Большинство проблем с длинными сессиями - именно отсюда.

## Адаптация под Контент-завод

- Handoff-файл класть в `retrospectives/YYYY-MM-DD_HH-MM_handoff-название.md`: что сделано, какая фаза в работе, что мешает, открытые вопросы. Новая сессия начинает с него.
- Стадии завода: разведка → чертёж (`architecture/`) → план (`plans/`) → реализация фазы → приёмка. Каждая - своё окно; `idea/` и `architecture/` не грузить целиком, только `SUMMARY.md`.
- Транскрипты эфиров (200 тыс. символов) - только через субагента с саммари, никогда напрямую в основной чат.
