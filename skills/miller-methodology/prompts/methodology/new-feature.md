# Шаблон Plan Mode: добавление новой фичи

**Когда применять:** для любой новой функции, у которой в проекте уже есть похожие (второй адаптер площадки, второй формат отчёта). Включай Plan Mode и вставляй шаблон, заполнив фигурные скобки.
**Источник:** гайд `plan-mode-v-claude-code` 382-403 («Шаблон 3. Добавление новой фичи»); `training/guides-review.md` §4.16.

## Промпт

```prompt
Включаю Plan Mode. Задача: добавить фичу {описание} в проект.

Шаг 1: Изучи как сейчас работают похожие фичи в проекте.
Конкретно посмотри:
- {файл-1}
- {файл-2}
- какие паттерны архитектуры используются
- какие тесты пишутся для подобных фич

Шаг 2: Найди как эта фича реализована в open-source проектах
с похожей архитектурой. Минимум 2 разных подхода.

Шаг 3: Составь план в plans/YYYY-MM-DD-feature-{name}.md:
- список новых файлов
- список изменяемых файлов с конкретными строками
- последовательность реализации
- какие тесты добавить
- что добавить в CLAUDE.md как правило для будущих сессий

Шаг 4: Самопроверка. План соблюдает архитектуру проекта?
Есть допущения о библиотеках, которые ещё не установлены?
```

После шага 4 - чек-лист 7 признаков плана (там же, 138-150): имена файлов, последовательность, зависимости, риски, критерии успеха, нет допущений «с потолка», помещается на экран. Он в `plans/TEMPLATE.md`, секция «Самопроверка плана».

## Адаптация под Контент-завод

- Шаг 1 для нас начинается с `architecture/SUMMARY.md` и файла узла в `architecture/`, а не с кода: чертёж отвечает «почему», код - «как».
- В шаге 3 добавить строку «какие ограничения площадки из `idea/principles.md` затрагивает» и «отправляющая часть выключена по умолчанию».
- Имя файла плана - по правилу `CLAUDE.md`: `plans/YYYY-MM-DD-название.md`, один план = одна функция.
- Дальше по цепочке: `three-questions-to-plan.md` → `notes-in-plan.md` → `guard-phrase.md`.
