# Разведка перед кодом: найти, как это уже решали

**Когда применять:** в самом начале большой задачи, до спецификации и плана. Когда чувствуешь, что ныряешь в реализацию без понимания «а как вообще принято такое решать».
**Источник:** Артемий Миллер, промпт №2 «Deep Research → Best Solution» (`training/source/promty/razvedka-pered-kodom-naiti-kak-eto-uzhe-reshali.md`).

## Промпт

```prompt
Режим: только чтение. Никакого кода.

Задача исследования: {опиши задачу}

Действия:
1. Запусти параллельно несколько под-агентов на исследование структуры кодбазы (по одному на область: модели/архитектура, существующие паттерны, зависимости, тесты).
2. WebSearch: кто уже решил эту проблему? Какой подход выбрали? Какое решение считается best practice сегодня?
3. Собери все находки в один артефакт.

Артефакт исследования ОБЯЗАН заканчиваться разделом «Рекомендация»:
- Какое решение выбрано как лучшее.
- Почему именно оно (сравнение с 2-3 альтернативами).
- Что нужно учесть при имплементации.

Не вываливай на меня список опций без вывода. Без рекомендации - артефакт неполный.
```

## Почему работает

Большинство задач уже кем-то решены. Промпт заставляет агента сначала найти существующие подходы, а потом синтезировать вывод-рекомендацию, а не вываливать список опций.

## Адаптация под Контент-завод

- Артефакт исследования класть в `.business/research.md` (группы «беру / не беру / потом»), а не в чат - его читает план (`plan-three-passes.md`).
- Для узлов публикации разведка обязана проверить ограничения площадки из `idea/principles.md` (лимиты API, бан за автоматизацию) - «best practice» с Запада может быть запрещена в Дзене или VK.
- Референсы уже собраны в `idea/references.md` - начинать с них, WebSearch поверх.
