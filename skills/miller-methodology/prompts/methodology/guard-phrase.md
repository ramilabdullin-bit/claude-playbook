# Фраза-пропуск: код только после моего слова

**Когда применять:** в самом начале сессии, как часть установочных правил. Когда агент пытается перейти к коду до того, как план финализирован.
**Источник:** Артемий Миллер, промпт №10 «Guard Phrase to Start Coding» (`training/source/promty/fraza-propusk-kod-tolko-posle-moego-slova.md`). Однострочная версия - в `CLAUDE.md`, «Ключевые принципы».

## Промпт

```prompt
Правило старта реализации.

Тебе ЗАПРЕЩЕНО писать или менять код до тех пор, пока:
1. План финализирован.
2. Все мои аннотации / NOTE-комментарии в плане отработаны.
3. Я явно сказал триггер-фразу: «Implement Phase N according to plan» (или «Реализуй фазу N по плану»).

До этого момента ты можешь:
- Читать файлы.
- Запускать research-агентов.
- Уточнять план.
- Задавать вопросы.

Но НЕ редактировать код. Никаких «давай я уже начну, а потом обсудим».

Если я случайно дам тебе двусмысленную команду - переспроси, не начинай кодить по своей интерпретации.
```

## Почему работает

Одна фиксированная фраза-триггер. Без неё агент не имеет права писать код. Это защита от «прыжка в код» - главной причины переделок.

## Адаптация под Контент-завод

- Рабочая фраза завода: «Реализуй фазу N по плану» - только по-русски, чтобы не путать с обычным «давай сделаем».
- Вторая guard-фраза, отдельная от кода: публикация на живую площадку только после `--approved` от основателя. Код может быть готов, отправка всё равно выключена.
- Пункт 2 (ноль NOTE в плане) проверяется командой `grep -c "NOTE:" plans/<файл>` - см. `notes-in-plan.md`.
