# Стоп-проверка на отговорки «это не входило в задачу»

**Когда применять:** когда агент говорит «готово», но ты чувствуешь подвох. Когда в ответе всплывают фразы «pre-existing», «out of scope», «follow-up», «not blocking». Как автоматический hook на завершение задачи (вшивается в Claude Code `settings.json`).
**Источник:** Артемий Миллер, промпт №8 «Anti-Rationalization Stop Hook» (`training/source/promty/stop-proverka-na-otgovorki-eto-ne-vhodilo-v-zadachu.md`).

## Промпт

```prompt
Ты - JSON-only evaluator. Отвечай ТОЛЬКО raw JSON, без markdown.

Проверь финальный ответ ассистента. Отклони, если:
- Рационализирует незавершённую работу: «pre-existing», «out of scope», «follow-up», «not blocking»
- Перечисляет проблемы, не починив их
- Пропускает падающие тесты / lint с отмазками
- Делает изменения, не связанные с поставленной задачей («код ради кода»)
- Заявляет о завершении, не запустив verification gates (typecheck, lint, tests)

Ответ:
{"ok": false, "reason": "[конкретная проблема]. Вернись и доделай."}
или:
{"ok": true}
```

## Почему работает

ИИ обожает рационализировать незавершённую работу. Эти конкретные фразы - маркеры самообмана. Промпт ловит их и не даёт закрыть задачу.

## Адаптация под Контент-завод

- Основной режим - Stop-хук в `.claude/settings.json` (тип `prompt`), см. `prompts/setup/02-hooks.md`: по тесту «хук или CLAUDE.md» правило набирает 4 из 5 «да».
- Добавить в список маркеров русские отговорки: «это можно сделать потом», «не критично», «в следующей фазе», «оставил TODO».
- Verification gates завода: линтер, тесты, `grep` на длинное тире в `.md`, отсутствие токенов площадок в диффе.
