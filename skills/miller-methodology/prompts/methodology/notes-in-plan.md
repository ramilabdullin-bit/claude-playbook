# Правки в плане на полях, а не переписывание

**Когда применять:** когда агент сделал первый драфт плана / спеки / архитектуры. Когда у тебя есть конкретные правки, но проще написать их прямо в файле, чем перечислять в чате.
**Источник:** Артемий Миллер, промпт №11 «Annotation Cycle» (`training/source/promty/pravki-v-plane-na-polyah-a-ne-perepisyvanie.md`).

## Промпт

```prompt
Workflow совместного редактирования плана:

1. Ты драфтишь план / спеку / документ в файл.
2. Я открываю файл в редакторе и добавляю комментарии в формате:

   > NOTE: тут не учёл случай X, переделай
   > NOTE: эту фазу разнеси на 2 - слишком большая
   > NOTE: вместо подхода А используй Б, потому что...

3. Я говорю тебе: «Address all notes, don't implement yet» (или «Отработай все NOTE, не реализуй»).
4. Ты проходишься по каждому NOTE, изменяешь план, удаляешь NOTE после отработки.
5. Возвращаешь обновлённый план.
6. Повторяем, пока в файле не останется ни одного NOTE.

Только после этого план считается финализированным и готовым к реализации.

Это лучше, чем я буду перечислять правки в чате - ты увидишь каждую правку в её естественном контексте.
```

## Почему работает

Самый эффективный паттерн совместной работы с ИИ над документом. Ты не перечисляешь правки голосом, а вписываешь их в файл - агент видит весь контекст и не теряется.

## Адаптация под Контент-завод

- Работает не только для `plans/`, но и для `architecture/*.md` и `idea/*.md`: правки в чертёж - тоже `> NOTE:`.
- Команда фиксирована: «Отработай все NOTE, не реализуй». План финализирован = ноль NOTE (правило в `plans/README.md`).
- Голосовой ввод: надиктовать NOTE прямо в файл через Wispr Flow быстрее, чем пересказывать в чате.
