# Самопроверка по спеке перед словом «готово»

**Когда применять:** сразу после того, как агент завершил кусок реализации - до того, как сказал «готово». Перед коммитом / мержем / показом тебе.
**Источник:** Артемий Миллер, промпт №5 «Self-Audit после каждой фазы» (`training/source/promty/samoproverka-po-speke-pered-slovom-gotovo.md`).

## Промпт

```prompt
Аудит реализации текущей фазы. Свежими глазами.

1. SPEC COMPLIANCE
   Открой спеку. Пройдись по каждому acceptance criterion.
   Для каждого: реализован? Где именно в коде (файл:строка)?
   Если хоть один не покрыт - закончи его сейчас, не оставляй на «потом».

2. CHALLENGE THE SOLUTION
   Посмотри на написанный код свежими глазами.
   - Это правда решает задачу из спеки?
   - Есть ли способ проще / эффективнее?
   - Есть ли «код ради кода» - изменения, не связанные с задачей? Удали их.

Только после этого можешь сказать «фаза завершена».
Запрещено говорить «готово», если хоть один criterion не покрыт.
```

## Почему работает

ИИ часто рапортует «готово», когда покрыто 70% требований. Промпт заставляет агента самого свериться со спекой и честно сказать, что не сделано.

## Адаптация под Контент-завод

- «Спека» = DoD фазы в файле плана `plans/`. Отметка `[x]` в плане ставится только после этого аудита.
- Это самопроверка автора. Внешняя приёмка - отдельно: `acceptance.md` (доказательства командами) и субагент `.claude/agents/qa-acceptor.md` (чистый контекст, цель - опровергнуть).
- Для узла публикации критерий «опубликовано» = JSON ответа API площадки + ссылка на пост, а не «код написан».
